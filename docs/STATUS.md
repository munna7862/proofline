## Sprint 2 candidates
From S1-T6 (evidence in the trial branches `proofline-trial` of each repo; ranked by impact on trust in the numbers):

| # | Misclassification | Evidence | Proposed fix |
|---|---|---|---|
| 1 | **Link-destination rule inflates coverage.** A link counts as tested when any test visits its destination, even if nothing clicked it. | buggy-books: 59 of 106 "tested" elements had no interaction; interaction-only score is 33.3%, not 75%. Every header link is "tested" on every view. | Scoring change (needs approval): count links as tested only on interaction, or show "reached by URL" as a separate, unscored state. Calibration entry required. |
| 2 | **Unnormalized ids and slugs in views and endpoints.** cuid/cuid2 ids (`cmusge6wr0004pndce18dw4iq`, `fdf6qsvrkvfnw2ctkcjhdsog`) and faker usernames (`/users/ag_theodora_conroy`) are kept verbatim. | epic-stack: 9 page types become 32 views; denominator moves 554 → 680 between identical runs. 4 of 4 faults on per-user endpoints are "not reached" because each run creates a new user. | Normalize cuid/cuid2/nanoid/ulid shapes (mixed letters+digits, length ≥ 20) in `normalizePath` and the agent copy; learn params from data (segment that differs per test under the same parent → `:param`); `viewRules` in proofline.config.json. |
| 3 | **Equivalent faults counted as "slipped".** Injecting 500/network failure on an endpoint that already errored in baseline changes nothing. | buggy-books `POST /api/auth/refresh`: baseline 401 (test clears cookies and expects a redirect to /login); 500 and network-fail "survived", making UI_REF_02 the "weakest test". | Record baseline status per endpoint; mark http-500/network-fail as not-applicable when baseline was already 4xx/5xx. |
| 4 | **`--max-mutants` picks by URL order, not impact.** | buggy-books: 20 faults covered 4 of 18 endpoints (`/api/auth/refresh` with 1 test in, `/api/login`, `/api/checkout/process` out). epic-stack: 7 of 55. | Order by number of dependent tests, round-robin across endpoints, still deterministic. |
| 5 | **Busy-state labels and input values become element names.** | buggy-books: "Authenticating...", "Creating account...", "Processing..." (×2), "Uploading Picture..." are untested phantom elements; the file input appears as 4 elements named after the selected file (`C:\fakepath\valid_avatar.png`). Login inputs get two names when a chaos toggle removes `<label for>`. | Never use `value` as a name for file inputs; skip `disabled`/`aria-busy` elements in inventory; fall back to stable `id`/`name` before placeholder. |
| 6 | **Shared header/nav counted once per view.** | buggy-books: 66 of 141 denominator rows are the same 10 header elements across 8 views; "Logout" is untested on 4 views and tested on 2. | Group elements inside `header`/`nav` landmarks that appear on ≥ 3 views into one "Shared" view. |
| 7 | **Scan time.** Killed faults wait out every failing test's timeout. | buggy-books: 45 min for 20 faults; each `GET /api/books` kill took ~9 min (31 tests × 30 s timeout / 2 workers). Phase 2 target is < 20 min for 100 tests. | Sprint 4 `--budget`; option to stop a fault run at the first failure (trades per-test strength detail for speed). |
| 8 | **Non-JSON data endpoints.** React Router/Remix `.data` responses are turbo-stream, so only 2 of 5 operators apply. | epic-stack: 0 body faults possible on 55 endpoints. | Phase 2+: turbo-stream aware body operators, or document the limitation. |
| 9 | **Framework fallbacks hide faults** (unverified). React Router appears to recover from a failed `.data` load with a document request. | epic-stack `GET /onboarding.data` 500 and network-fail "survived"; `POST /auth/github.data` and `POST /onboarding.data` "not reached" even though baseline recorded them. | Investigate with `replay`; candidate for "no visible effect" triage (Sprint 4). |
| 10 | Small items. | Infrastructure endpoints (`/socket.io` polling, the suite's `/api/test/*` backdoors) are fault targets. "No coverage recorded. Did your tests import…" also prints when every test failed to launch the browser. CLI prints "Fault check 0%" when 0 faults were judged (should be n/a). README should show `reporter: [['html'], ['proofline/reporter']]` for configs that use a string reporter. Git Bash rewrites `--include /notes` into a Windows path; docs should say to drop the leading slash. | Default excludes + config; better messages; docs. |
